# Перенос Telegram-бота с Railway на VPS: как проверить копию SQLite

Бот отвечает после переезда, но последние записи пропали. Так бывает, если скачать один `bot.db` из работающего приложения. В режиме WAL подтверждённые транзакции могут ещё лежать в `bot.db-wal`. SQLite откроет старый файл, и `PRAGMA integrity_check` может вернуть `ok`.

На локальном Linux-стенде модель polling-бота подтвердила обновление №41. Мы сняли две копии в один момент. Обе по 12 288 байт, обе прошли `integrity_check`.

| Копия | Обновление №41 | Следующий offset |
| --- | --- | --- |
| Скопировали только `.db` | Нет | 41 |
| Снимок через SQLite `.backup` | Есть | 42 |

Offset — первый ID, который приложение запросит через `getUpdates`. В нашей модели он лежит в базе. У вашего бота он может храниться отдельно или вычисляться иначе. Стенд работал локально, с синтетическими обновлениями.

## Проверьте восстановление до отключения Railway

1. В настройках приложения найдите фактический путь к базе и определите, лежит ли она на томе или в файловой системе контейнера. Сделайте предварительный согласованный снимок SQLite, пока доступ к контейнеру работает. `railway run` запускает команду на вашей машине, для файлов работающего сервиса нужен `railway ssh`. Сохраните отдельно файлы состояния, если приложение хранит их за пределами базы. [Документация `railway run`](https://docs.railway.com/cli/run)
2. Скачайте снимок в приватное место через [Railway SSH/SFTP](https://docs.railway.com/cli/ssh#copy-files-with-scp-and-sftp). Из контейнера, который уже остановлен, этот способ файлы не забирает. Если старого экземпляра уже нет, начните с проверки имеющихся резервных копий.
3. На VPS откройте копию в отдельном каталоге и проверьте `PRAGMA integrity_check;`. Сверьте количество записей и несколько недавних контрольных записей с исходником. Не запускайте тестовый экземпляр с действующим токеном.
4. В согласованное окно остановите обработку обновлений и дождитесь завершения записи. Доступ к исходным файлам должен сохраниться, например через предусмотренную приложением паузу в том же контейнере. Если остановка poller завершает весь контейнер, заранее отрепетируйте другой способ экспорта. Сделайте и проверьте финальный снимок. Перед запуском нового poller убедитесь, что прежний остановлен и не запустится автоматически. Проверьте ответ бота и новую запись после переключения.

Замените пути фактическими и используйте новый файл в закрытом каталоге. Нужны доступ на чтение к базе и её WAL/SHM либо возможность SQLite создать эти файлы рядом. Используйте поддерживаемую сборку SQLite с исправлением WAL-reset. На проверке ждите результат `ok`.

```sh
umask 077
sqlite3 -batch -bail -readonly /data/bot.db '.backup /private-export/bot.sqlite3' &&
  sqlite3 -batch -bail -readonly /private-export/bot.sqlite3 'PRAGMA integrity_check;'
```

Если новый экземпляр уже записал данные, старый файл устарел. На стенде запись №43 была только у нового процесса. Возврат к старому файлу её бы потерял. Для отката остановите новый процесс и сначала сверяйте изменения в базе и внешние действия. Например, вызов `getUpdates` с увеличенным offset может подтвердить обновления: повторная доставка после возврата старой базы не гарантируется.
